## 4. 升級／部署注意事項

- **這是第一個版本，沒有升級路徑**，不需要資料搬遷。
- **本機執行**：依 `README.md`「快速開始」的方式一（Docker Compose，實測 27 秒）或方式二（本機 Node，實測 14 秒）。兩種方式在 Git Bash 與 PowerShell 皆已實測可用。方式二需注意 `.env` 不會被自動載入，README 附了兩種 shell 的載入指令。
- **資料庫 migration 必須先 `npm run build`**（腳本讀編譯後的 `dist/db/migrate.js`），部署順序固定為 **build → migrate → deploy**。
- **部署一次新版本**：推上 `main` 且 CI 全綠即自動觸發 staging 部署。**目前此路徑被 KL-5 擋住**，解除方式見該列。
- **倉庫中不存在任何憑證值**，也不使用長期服務帳號金鑰；部署權限一律以 Workload Identity Federation 換取短期憑證。機密一律由 Secret Manager 注入，且**釘定具體版本號**（不再使用 `latest`，避免首個修訂版解析到舊值）。
- **發布前請輪換 staging 的 Basic Auth 帳號密碼**（Gate 2 條件 C-2）。
- **回滾**：首選是把 Cloud Run 的流量切回前一個修訂版，目標 2 分鐘內完成（實際演練為 **9.7 秒／10.4 秒**，兩次切換期間 `/health` 皆 200）。完整程序、備選方案（以 git 回復並重新部署）與資料庫層的處置見 **`docs/specs/06_部署架構與CICD.md` 第 5 章「回滾程序」**（§5.1 首選、§5.2 備選、§5.3 資料庫層、§5.4 演練紀錄）；可直接執行的腳本為 `scripts/rollback-staging.sh`。
