# 測試案例：E-001 待辦事項 Web 應用

每案例必須對應 US-ID / AC-ID。層級：unit / integration / e2e / uat / perf。
執行策略、退出準則、缺陷分級見 `docs/specs/07_測試計畫.md`；US↔TC 的對應同步登錄於 `docs/specs/traceability.md` 主表 TC 欄。

## 閱讀約定

- **TC-ID 連號**，TC-001 ~ TC-123，不重用、不跳號。
- **優先級**：`P0` = Gate 2 擋關（TC-001 ~ TC-105）；`P1` = **Gate 2 後**執行（TC-106 ~ TC-123，第 7 章）。
- **自動化**：`是` = 由 `ci.yml` 或可重跑腳本執行；`否` = 需人親自操作或計時（uat 層級一律為否）。
- **`{id}`** 表示前置條件中建立的待辦識別碼（UUID，O-007）。
- **`$B`** 表示 Basic Auth 參數 `-u "$STAGING_BASIC_AUTH_USER:$STAGING_BASIC_AUTH_PASSWORD"`。**報告中一律以變數呈現，不得貼出實值。**
- **特殊判準**：AC-009-3、AC-009-5、AC-010-5、AC-013-2、AC-002-4 五條 AC 的斷言，一律以 `traceability.md`「特殊驗證方式的 AC」表為準，本檔不自行重新解讀。
- 錯誤物件結構固定為 `{code, message, details?, requestId}`（SD 6.1）；錯誤碼為 `E_VALIDATION`(400)、`E_UNAUTHORIZED`(401)、`E_NOT_FOUND`(404)、`E_EMAIL_TAKEN`(409)、`E_INTERNAL`(500)。
