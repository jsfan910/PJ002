## Pipeline 修正（落實 D-018）

- `.github/workflows/deploy-staging.yml`、`scripts/deploy-staging.sh`：`gcloud run deploy` 後新增流量驗證。主判準為直接讀 `status.traffic`，加總本次剛部署的 revision 拿到的百分比並要求等於 **100**；`status.latestReadyRevisionName` 是否等於該 revision 併作輔助佐證（此欄位在 Cloud Run 實際會跟隨接流量的 revision，已於本次事故復原時實測確認，但屬平台未文件化行為，單看它會漏判分流／canary 情境，故不單獨作為判準——dev-tl 初審 r1 指出後修正）。未達 100% 即自動 `update-traffic --to-latest` 並重新輪詢 `/health`、重新驗證，仍未達才 `::error::` 判紅（workflow）或非 0 結束並印出流量分佈（本機腳本）。`GITHUB_STEP_SUMMARY` 新增「部署流量檢查」表格記錄 revision 名稱與 `status.traffic` 實際讀到的流量百分比。

- `README.md`「部署與 secrets」章節同步上述行為與警語。
- 離線驗證：`actionlint`（0 finding）、`yaml-lint`（成功）、`bash -n`（語法正確）皆通過；`scripts/rollback-staging.sh --to-latest` 已用本機已登入的 owner 帳號實跑一次（冪等，未變更現況），確認新模式可正確執行。**依 §6.9.1 教訓，CI 實際使用 WIF 服務帳號、權限與本機 owner 帳號不同，離線驗證不能保證真實 run 會通過**——已於上方「真實部署重測」段落以真實 run `35513187463` 補證，`conclusion=success`。
