## 結論摘要

**staging 尚未部署成功**。`deploy-staging.yml` 已在 main 綠燈後真實觸發兩次，兩次都在第一個階段（`auth`，Workload Identity Federation）失敗，錯誤訊息一致：

```
google-github-actions/auth failed with: failed to generate Google Cloud federated token for //iam.googleapis.com/***:
{"error":"unauthorized_client","error_description":"The given credential is rejected by the attribute condition."}
```

**根因（已用本機已登入的 `gcloud` 唯讀查詢確認，未修改任何設定）**：GCP 端 WIF provider（`github-pool`／`github-provider`）的 `attribute-condition` 目前的值是**字面佔位符**，並未替換成實際倉庫：

```
attributeCondition: assertion.repository == '<owner>/<repo>'
```

正確值應為：

```
assertion.repository == 'jsfan910/PJ002'
```

因為條件字面比對永遠不成立（沒有任何 GitHub 倉庫的名字是字串 `<owner>/<repo>`），所以**任何**倉庫（包括正確的 `jsfan910/PJ002`）換發的 OIDC token 都會被拒絕。這正是 `README.md`「部署與 secrets」第 4 步 ② 指令裡 `--attribute-condition="assertion.repository == '<owner>/<repo>'"` 的角括號佔位符未被替換所致——已在本次收尾把這個真實案例補進 README 新增的「GCP 指令在哪裡執行」一節，提醒日後任何人設定 WIF 時務必替換。

**這是 GCP 設定問題，不是 workflow 程式問題**：`deploy-staging.yml`、`monitor-health.yml`、`infra/cloudrun-service.yaml`、`scripts/*.sh` 皆未變更任何部署邏輯，本卡只新增 README 一段說明與 06 文件三處實作紀錄。**agent 已依規定不索取、不代填、不修改任何 GCP IAM／安全性設定**，只做唯讀查詢定位根因；修正指令列在下方「使用者要做的事」，需使用者自行執行。

## 遇到的問題與解法

1. **WIF attribute-condition 字面佔位符未替換**（見上方「結論摘要」）。解法：使用者執行下方修正指令後，重新觸發 `deploy-staging.yml`。
2. **本機 `gcloud`／`gcloud.cmd` 不在 PATH**：Git Bash 下 `gcloud` 找不到指令；PowerShell 下 `gcloud.cmd` 同樣找不到。改用完整路徑 `"$env:LOCALAPPDATA\Google\Cloud SDK\google-cloud-sdk\bin\gcloud.cmd"` 執行唯讀查詢成功（帳號已於先前 `gcloud auth login` 完成，agent 未代登入，只使用既有登入狀態）。**建議使用者把該路徑加入使用者 PATH**，之後可直接打 `gcloud.cmd`（PowerShell／cmd.exe）或 `gcloud`（Git Bash，若安裝時已建立 POSIX 包裝）。
3. **`monitor-health.yml` 尚無 run**：GitHub 排程工作流在剛併入 main 後常有數分鐘至數十分鐘的觸發延遲，非程式問題。agent 無 GitHub 登入，無法手動 `workflow_dispatch`；已在 06 §6.5 記錄為「遠端待驗」。

## 使用者後續要做的事（依優先序）

1. **修正 WIF attribute-condition**（唯一已知阻擋根因；本步驟屬安全性設定變更，agent 依規定不代為執行）：

   Git Bash：
   ```bash
   gcloud iam workload-identity-pools providers update-oidc github-provider \
     --project="pj002-509106" --location="global" --workload-identity-pool="github-pool" \
     --attribute-condition="assertion.repository == 'jsfan910/PJ002'"
   ```

   PowerShell（若 `gcloud.cmd` 不在 PATH，前面加完整路徑）：
   ```powershell
   gcloud.cmd iam workload-identity-pools providers update-oidc github-provider `
     --project="pj002-509106" --location="global" --workload-identity-pool="github-pool" `
     --attribute-condition="assertion.repository == 'jsfan910/PJ002'"
   ```

   修正後建議立即唯讀確認（不會修改任何東西）：
   ```bash
   gcloud iam workload-identity-pools providers describe github-provider \
     --project="pj002-509106" --location="global" --workload-identity-pool="github-pool" \
     --format="value(attributeCondition)"
   # 預期輸出：assertion.repository == 'jsfan910/PJ002'
   ```

2. **重新觸發 `deploy-staging.yml`**：到 https://github.com/jsfan910/PJ002/actions/workflows/deploy-staging.yml 登入後點 **Run workflow**（`workflow_dispatch`），或對失敗的 run 頁面點 **Re-run all jobs**。agent 無 GitHub 登入，這一步需使用者手動點擊。

3. **部署成功後回填三處**（dev-tl 審核時或使用者自行）：
   - 從該次 run 的 `GITHUB_STEP_SUMMARY`（或 `gcloud run services describe todo-app --region asia-east1 --format="value(status.url)"`）取得 `*.run.app` 網址。
   - GitHub repository variable `STAGING_BASE_URL`（Settings → Secrets and variables → Actions → Variables）填入該網址。
   - `docs/specs/06_部署架構與CICD.md` 第 1 章 staging 列、`docs/specs/04_API規格.yaml` 的 `servers` 區塊 staging 項，兩處都把佔位符換成實際網址（下一輪 dev-ops 或審核者可代填，不含憑證）。

4. **三條 staging 驗證**（回填網址後執行，憑證用環境變數，不入報告）：
   ```bash
   curl -sS -o /dev/null -w "%{http_code}\n" "$STAGING_BASE_URL/health"          # 期望 200，無憑證
   curl -sS -o /dev/null -w "%{http_code}\n" "$STAGING_BASE_URL/"                # 期望 401，無憑證
   curl -sS -o /dev/null -w "%{http_code}\n" -u "$STAGING_BASIC_AUTH_USER:$STAGING_BASIC_AUTH_PASSWORD" "$STAGING_BASE_URL/api/v1/todos"   # 期望 200，帶憑證
   ```

5. **回滾演練**（06 §5.4，Gate 2 前置條件）：待第一次成功部署後，執行一次會啟動失敗的版本驗證 startup probe 擋下、再部署一版能啟動但行為有誤的版本，用 `scripts/rollback-staging.sh <revision>` 或 `gcloud run services update-traffic` 切回，記錄耗時與驗證輸出於 06 §5.4。

6. **monitor-health.yml 首次採樣**：可等 cron 自然觸發（每 5 分鐘），或到 https://github.com/jsfan910/PJ002/actions/workflows/monitor-health.yml 登入後點 **Run workflow** 立即跑一次。`STAGING_BASE_URL` 填好之前，取樣會顯示 `::notice::` 並以 0/0 略過，不算成功採樣。
