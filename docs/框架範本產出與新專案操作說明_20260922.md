## 1. 三個東西的關係

```
框架來源 repo（本 repo：soft-dev-team-260919）
   │  改角色檔、模板、技能、計畫書、CLAUDE.md 都在這裡改
   │
   │  bash scripts/export-framework.sh <目標>
   ▼
乾淨範本（framework-template/ 快照，或任何指定目錄）
   │  零專案內容：只有規則、角色、技能、模板、腳本、空目錄、空看板
   │
   │  複製 → 改名 → git init → 開新 Claude Code session
   ▼
新專案資料夾（各自獨立、各自 git、各自 Claude Code session）
```

- **改框架**永遠在來源 repo 改，然後重新匯出。快照只是「匯出結果的存檔」，方便直接複製或做成 GitHub template repository。
- **新專案**從快照複製後就與來源脫鉤；之後框架更新不會自動同步，要手動挑檔案覆蓋（見第 6 節）。

## 2. 產出範本（在框架來源 repo 執行）

### 2.1 指令

```bash
cd /c/Users/excal/Projects/Claude/soft-dev-team-260919
bash scripts/export-framework.sh framework-template
```

- 第一個參數是目標目錄；可以是 repo 內的 `framework-template`（更新快照），也可以是任何外部路徑（例如 `/d/work/my-new-project`，直接匯出成新專案）。
- **腳本會先清空目標目錄再重建**，不要指向已有專案內容的資料夾。
- 腳本有安全檢查：目標不得是來源 repo 本身或其上層。

### 2.2 腳本做的九件事

| 步驟 | 內容 |
|---|---|
| 1 | 清空目標目錄 |
| 2 | 建目錄骨架：`.claude/{agents,skills}`、`docs/{templates,specs/adr,reports,archive,schedule}`、`tasks`、`worklog/{handoff,daily_summary}`、`scripts`、`ref`、`src`、`tests`（空目錄放 `.gitkeep`） |
| 3 | 原樣複製：12 個角色檔、5 個技能、25 份模板、`scripts/extract-cards.sh`、`scripts/gen-schedule.mjs`、`scripts/export-framework.sh` 自身、`.gitignore` |
| 4 | 去專案化角色檔／技能／模板／腳本：把首輪試跑的 Epic 代號與來源目錄名替換成中性字串 |
| 5 | 產生 `CLAUDE.md`：以來源 `CLAUDE.md` 為底，文件地圖的計畫書改指向 `docs/團隊協作計畫書.md`，移除專案句；協作協定、回報規則、收工規則、工作鐵則全部保留，並加註「鐵則括號內的日期與卡號是歷史案例來源」 |
| 6 | 產生 `docs/團隊協作計畫書.md`：去掉首輪的裁決結果與專案數據，保留架構、必產文件與 DoD、模型表、流程（含 7.6 Gate 2 補驗子流程）、風險、附錄 B 變更紀錄；第 10 章保留 5 題作為新專案開場問卷 |
| 7 | 產生空看板 `tasks/_todo.md`（四張表）、`tasks/_done.md`（含派工／完成時間欄）、`docs/archive/_index.md` |
| 8 | 產生 `docs/schedule/example.json`（Epic E-000 的空設定檔，九個階段鍵值） |
| 9 | 產生 `README-框架.md`（新專案起手式六步、目錄說明、不包含什麼、怎麼更新） |

### 2.3 匯出後的驗證（每次都做）

```bash
# 專案字樣不得殘留（預期 0 行；唯一允許的是計畫書範例列裡的示意日期）
grep -rnE "E-001|pj002|jsfan910|todo-app|run\.app|Neon|Render" framework-template

# 數量：60 檔、12 角色、5 技能、25 模板

cd framework-template && : > cards.txt && node scripts/gen-schedule.mjs docs/schedule/example.json cards.txt --out "$TEMP/x.html" && cd ..
```

### 2.4 快照同步檢查（收工必做）

框架來源改了但忘了重新匯出，快照就會過時。收工規則已納入：

```bash
bash scripts/export-framework.sh "$TEMP/fw-check" && diff -rq "$TEMP/fw-check" framework-template
```

沒有輸出代表同步；有差異就重跑 2.1 並 commit 快照。

### 2.5 commit

```bash
git add framework-template scripts/export-framework.sh
git commit -F <訊息檔>     # 多行訊息一律寫檔再 -F（工作鐵則）
git push origin main
```

## 3. 開新專案（六步）

以下以 Windows 11 為例；`/c/...` 是 Git Bash 路徑寫法，PowerShell 用 `C:\...`。

### 步驟 1：複製範本

Git Bash：
```bash
mkdir -p /c/Users/excal/Projects/Claude/my-new-project
cp -r /c/Users/excal/Projects/Claude/soft-dev-team-260919/framework-template/. /c/Users/excal/Projects/Claude/my-new-project/
```

PowerShell：
```powershell
New-Item -ItemType Directory -Force C:\Users\excal\Projects\Claude\my-new-project | Out-Null
Copy-Item -Recurse -Force C:\Users\excal\Projects\Claude\soft-dev-team-260919\framework-template\* C:\Users\excal\Projects\Claude\my-new-project\
Copy-Item -Force C:\Users\excal\Projects\Claude\soft-dev-team-260919\framework-template\.gitignore C:\Users\excal\Projects\Claude\my-new-project\
Copy-Item -Recurse -Force C:\Users\excal\Projects\Claude\soft-dev-team-260919\framework-template\.claude C:\Users\excal\Projects\Claude\my-new-project\
```

PowerShell 的 `*` 不含隱藏檔，所以 `.gitignore` 與 `.claude` 要另外複製；Git Bash 的 `.` 寫法會一起帶。

或者直接匯出到新目錄（省去複製）：
```bash
bash /c/Users/excal/Projects/Claude/soft-dev-team-260919/scripts/export-framework.sh /c/Users/excal/Projects/Claude/my-new-project
```

或在 GitHub 把 `framework-template/` 做成 template repository，之後用「Use this template」。

**複製後檢查**（缺一不可）：`.claude/agents/` 12 檔、`.claude/skills/` 5 個目錄、`docs/templates/` 25 檔、`CLAUDE.md`、`docs/團隊協作計畫書.md`、`.gitignore`。

### 步驟 2：改名

資料夾名就是專案名，沒有格式限制。計畫書第 3 章目錄圖用 `{專案根目錄}` 佔位，不必改。

### 步驟 3：納入版控

```bash
cd /c/Users/excal/Projects/Claude/my-new-project
git init -b main
git config user.name "excal"
git config user.email "excalibur.star@gmail.com"
git add -A
git commit -m "chore: 從框架範本建立專案"
```

版控是必要條件：每卡一分支、git worktree、CHANGELOG、回滾都建立在 git 上。要推到 GitHub 的話先在網頁建空 repo（不要勾初始化 README），再 `git remote add origin <url>` 與 `git push -u origin main`；第一次推送會跳 Git Credential Manager 的登入視窗。

### 步驟 4：確認工具鏈

| 工具 | 用途 | 檢查 | 何時需要 |
|---|---|---|---|
| git | 版控、worktree | `git --version` | 立刻 |
| Node.js 20+ | 時程表產生器；多數專案的前後端 | `node -v` | 立刻（時程表） |
| Git Bash | `scripts/*.sh` | `bash --version` | 立刻 |
| Docker Desktop | 容器化、本機整合測試 | `docker info` | 開發階段 |
| 雲端 CLI（例如 gcloud） | staging 部署 | 依平台 | 部署階段 |

缺的等用到再裝；框架不預設技術棧，由系統設計階段決定並寫 ADR。

### 步驟 5：開一個新的 Claude Code session

- 在 Claude Code 桌面版用「開啟資料夾」指向新專案目錄，開新 session。
- **必須是新 session**：`.claude/agents/*.md` 只在 session 啟動時載入；在舊 session 複製檔案叫不到新角色（工作鐵則）。
- 新 session 開始時 Leader 會依全域規則先檢查 `worklog/handoff/`，此時是空的，直接開工。

### 步驟 6：對 Leader 說需求

- 直接描述要做的產品或系統，越具體越好（要什麼、給誰用、優先順序、範圍外、限制）。有參考資料放進 `ref/`。
- Leader 會先回答計畫書第 10 章的 5 題開場問卷（git init 是否已做、模型模式、派工方式、CI 與雲端預設、需求來源），然後建 Epic 與第一批任務卡。
- **Phase 0（框架建置）已完成，直接從 Phase 1 開始**。整個流程您只會被問三次：① 計畫書確認 ② Gate 1 規格包 ③ Gate 2 可運行程式＋測試報告；外加任務卡 3 輪未過時的升級單。

## 5. 範本不包含什麼

- 任何專案的需求、規格、程式碼、測試、雲端設定：`docs/specs/`、`src/`、`tests/` 只有 `.gitkeep`。
- `.claude/settings.local.json`（個人權限，本來就不入版控；新專案第一次跑工具時自動產生）。
- CI/CD workflow 檔：由 dev-ops 依該專案的部署架構產生。
- 技術棧預設：語言、框架、資料庫、雲端一律由系統設計階段決定並寫 ADR。
- 歷史紀錄：`CLAUDE.md` 工作鐵則與計畫書附錄 B 的括號案例是首輪試跑的經驗來源，保留是因為下一個專案還會踩同樣的坑；不是新專案的事實。

## 6. 框架更新後怎麼同步到已在跑的專案

1. 在來源 repo 改（角色檔、模板、技能、計畫書、鐵則），走 Phase 2 流程（框架卡由 Leader 代理執行、Leader 審核）。
2. 重新匯出快照並 commit（第 2 節）。
3. 已在跑的專案**不要整包覆蓋**（會清掉專案內容）。手動挑檔案覆蓋，通常只有 `.claude/agents/`、`.claude/skills/`、`docs/templates/`；`CLAUDE.md` 的工作鐵則段可比對後合併。
4. 界線（計畫書第 9 章）：框架修正不回頭套用到進行中的 Epic，由下一個 Epic 驗證。
5. 覆蓋角色檔後要開新 session 才生效。

## 7. 常見問題

| 問題 | 原因與處理 |
|---|---|
| 新 session 派工時 Agent 工具說找不到角色 | 角色檔在 session 啟動後才複製進來。關掉 session 重開；或臨時用 `general-purpose` + 提示詞首行「先讀 .claude/agents/{role}.md 整份視為角色指令」（`dispatch` 技能有備援寫法） |
| Bash 指令失敗顯示 unexpected EOF | 指令列含 ASCII 單引號。改雙引號，或用 Write 工具寫成腳本再執行 |
| 指令卡住 120 秒 | 呼叫了 `python3`（Windows 應用程式執行別名）。改 sed／awk／grep 或 Write |
| sed 把一行截斷 | 分隔符用了 `#` 或 `|`（撞到 `T-####` 與表格）。改 `~` 或 `@`，或用 Edit 工具 |
| Docker 指令無回應 | Docker Desktop 未啟動。驗收改用 `npm start` 等離線替代並在交接檔註明 |
| PowerShell 執行 gcloud 被擋 | 執行原則禁止 `.ps1`。改打 `gcloud.cmd`，或在 Git Bash 用完整路徑 |
| 時程表看不到某張卡 | 該卡 `epic:` 與設定檔 `epic` 不同（產生器依 Epic 過濾）；或任務卡缺 `phase:`（回退到團隊預設階段，仍會顯示） |
| 匯出後 grep 有專案字樣 | 來源 repo 新增了含專案名的框架檔。在 `export-framework.sh` 第 4 步的去專案化規則補一條，重跑 |
