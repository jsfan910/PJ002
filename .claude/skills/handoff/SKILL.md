# /handoff — 收尾交接

判準：換一個 agent 明天早上只讀「任務卡 + 交接檔 B 段」，能不能直接開工？不能就是還沒交接完。

## 步驟

1. 找到本卡本輪的交接檔 `worklog/handoff/*-T####-r{round}-{role}.md`（開工時已建，含 A 段）。沒有就先依模板補建 A 段（註明「補建」）。
2. 逐條核對任務卡 `acceptance`。對每條**實際執行**驗收方式的指令，把指令與真實輸出貼進 B 段「驗證方式」。任一條不過：不得標 `review`，改標 `blocked` 或繼續修。
3. 填 B 段全部欄位。空的欄位寫「無」，不留空白。特別注意：
   - 「假設與決策」：每個你自己決定的事都要寫，含理由；
   - 「需要 Leader 裁決的事」：無法決定的事寫這裡，不要埋在正文。
4. 任務卡 frontmatter：`status` 改為指定值（預設 `review`）、`updated` 取實查系統時間；`blocked` 時填 `blocked_reason`。
5. **時戳格式驗證**（commit 前必做）。A 段「開工時間：」與 B 段「完工時間／狀態：」的時戳一律 `yyyy-mm-ddTHH:MM:SS+08:00`，不加括號註解、不省秒、不寫「約」。時程表抽取腳本靠這兩行定位，格式歪掉該卡就從甘特圖消失（T-0029 r1 已發生）。自己 grep 一次，看到兩行各一筆才算過：
   ```bash
   grep -nE "^- (開工時間|完工時間／狀態)：[0-9]{4}-[0-9]{2}-[0-9]{2}T[0-9]{2}:[0-9]{2}:[0-9]{2}\+08:00" worklog/handoff/{本檔}
   ```
   只回一行或零行 → 就是格式錯，改掉再繼續。時間取實查系統時間（`date +%Y-%m-%dT%H:%M:%S+08:00`），不要憑印象寫。
6. Git：
   - 開發卡：`git add` 本卡 `outputs` 與交接檔、任務卡；在 `task/T-####-slug` 分支 commit，訊息 `T-####: 摘要`。
   - 文件卡：直接在 `main` commit。
   - **多行 commit 訊息一律先寫檔再 `-F`**，不要用多個 `-m`，也不要在 `-m` 裡塞換行（本環境 Bash 指令不可含 ASCII 單引號，引號拼接必炸）：
     ```bash
     git commit -F "$TEMP/commit-T####.txt"
     ```
   - 只 `git add` 自己卡的 `outputs` 與交接檔、任務卡；禁止 `add -A`、`--amend`、`reset`、`rebase`（平行卡共用同一個 main，覆蓋別人的提交無法復原）。
   - 不 commit 任何 `.env`、憑證、暫存檔。
7. 回報五行：`狀態｜產出路徑｜交接檔路徑｜需裁決事項（無則寫無）｜下一步`。
