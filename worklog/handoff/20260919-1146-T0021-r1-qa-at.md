- 我做的假設與決策（含理由）：
  1. **`tests/integration/qa/**` 一律以真實 HTTP 呼叫 `$BASE_URL`，不沿用既有 `app.inject()` 匯入 `dist/` 的寫法**：理由是任務卡「現實條件」要求「測試程式以環境變數 BASE_URL 切換目標，日後對 staging 重跑不需改碼」，`app.inject()` 只能打進程內的 app 實例，換不了目標；HTTP 方式天然滿足這個需求，且不需要先 `npm run build`。
  2. **TC-087 的第 5 種情境（500）不在 `tests/integration/qa` 對共用服務觸發**：需真的斷線資料庫，具破壞性且會影響同時在跑的其他測試／服務；改為 `t.skip()` 並註記已由既有 `tests/integration/error-contract.test.ts`（dev-be，T-0016，以 `app.inject` 掛測試專用路由）覆蓋。
  3. **e2e 的 `.filter({hasText})` 鏈式定位在進入編輯模式後會失效**（`<input>` 的 value 不算入 `textContent`）：改用 `page.getByTestId(...)`（全頁面唯一，因同時只有一筆處於編輯狀態）取代 `item.getByTestId(...)`，已在 US-003、US-007（TC-064）、US-008（TC-066）、NFR-004（TC-091）四處統一套用此寫法。
  4. **`tests/perf/lib/load-runner.mjs` 的 `summarize()` 改用 `reduce` 而非 `Math.min(...values)`**：60 秒、10 併發取樣可累積數十萬筆耗時資料，展開成函式參數超過 JS 呼叫堆疊上限（實測 `RangeError`），已修正並重跑確認。
  5. **`tests/perf/tc094-nfr007-capacity.perf.mjs` 印出的清理指令改為在執行當下重新組出 `authorization`，不把組好的 Base64 字面值印進 stdout**：即使是本機佔位密碼 `dev/dev`，07 §6.2「任何憑證值不得出現在測試腳本、fixture、報告或截圖中」仍應遵守，已修正並重跑確認乾淨。
  6. **README TC-095 實測改用 `git archive HEAD` 匯出乾淨目錄**（而非要求真人開新機器）：任務卡要求「在乾淨目錄依 README 方式一與方式二各做一次」，agent 沒有另一台機器，`git archive` 匯出不含 `.git`／`node_modules`／`dist` 的乾淨副本，且不參考原始碼、逐字依 README 操作，效果等同「乾淨環境」。埠因與平行 worktree 衝突改用 8096／8098，不影響計時結果（README 字面 8080 已由 dev-tl 於 T-0018 逐字驗證過）。
