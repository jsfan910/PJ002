- 我做的假設與決策（含理由）：
  - S-11 的 `npm run dev` 拆成 `dev:build`／`dev:run` 兩個 script、不嘗試用 shell `&` 背景寫法湊成單一 `dev` script：`&` 背景寫法在 Git Bash 可行但 PowerShell 語意不同，會製造「看似能用但其實只在一種 shell 下正確」的假象，與專案「Git Bash／PowerShell 兩種寫法皆驗證過」的一貫要求衝突；任務卡本身也明文指定此方案。
  - `tsconfig.test.json` 加 `allowJs: true`／`checkJs: false`：僅為了讓 `tsc` 對 `import ... from "../../dist/xxx.js"` 不因缺少 `.d.ts` 而報 `TS7016`（主 `tsconfig.json` 的 `declaration: false`，不打算為此改動主設定）；`checkJs: false` 確保不會反過來對編譯產物的 `.js` 內容做型別檢查，型別檢查的對象仍是測試檔本身。這會讓「匯入自 `dist/` 的符號」型別退化為 `any`，犧牲一部分型別檢查覆蓋（換不到 `dist/*.js` 本身的型別安全），但保留了對測試檔**自身邏輯**（例如本卡修的 8 個 `todo` 參數、mock 簽名）的檢查，符合 CR S-4「型別錯誤要到執行期才炸」的主要訴求；若要更完整的型別覆蓋，正確做法是主 `tsconfig.json` 開 `declaration: true` 產生 `.d.ts`，但那屬於 src 建置設定變更，超出本卡授權範圍，寫進「下一步建議」。
  - `tsconfig.test.json` 覆寫 `rootDir: "."`：主設定的 `rootDir: "src"` 會讓 `tests/**` 檔案被判定「不在 rootDir 之下」（`TS6059`）；`noEmit: true` 下这個檢查仍會生效，覆寫為專案根目錄可解決，且不影響 `build`（`tsconfig.test.json` 從未被 `build` script 使用）。
  - `tests/unit/todo-repository.test.ts` 的 mock `query<T extends Record<string, unknown>>` 改為 `query<T = Record<string, unknown>>`：純粹讓 mock 的方法簽名與 `src/repositories/todo-repository.ts` 匯出的 `Queryable.query<T = Record<string, unknown>>` 完全一致（多了 `extends` 限制會讓 mock 的方法在結構上「更窄」，TS 判定不可賦值給介面）；只改測試檔簽名，未動 `src/`。
  - `tests/integration/todo-repository.test.ts` 8 個 `(todo) =>` callback 補 `(todo: { id: string })` 標註：只用到 `.id` 欄位，用最小結構型別即可消除 `TS7006`，不需要匯入完整 `Todo` 型別（`dist/` 匯入在本情境下型別已退化為 `any`，寫更完整的型別註記也拿不到額外檢查效益）。
  - 06 文件新增的第 7 節只做「記錄現況＋標註已知飄移」，未建議或代為修正 `allow-unauthenticated`／probe 兩項飄移：任務卡明文「僅新增一節」，且這兩項飄移本身是 ADR-0005 授權 dev-ops 決定去留的既有取捨（T-0018 交接檔已自陳），不在本卡 S-9 acceptance 的修正範圍內。
