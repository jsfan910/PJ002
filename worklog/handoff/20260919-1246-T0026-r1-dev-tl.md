**（a）一般快速切換三次以上**：依序點「未完成→已完成→未完成→已完成→未完成」五連點後立即讀取畫面：


**（b）人為製造「先發後到」（強化驗證，證明真的是 `requestSeq` 在擋而非機器太快）**：以 `javascript_tool` 對 `window.fetch` 加裝延遲，僅讓 `status=active` 的回應延後 1500ms：

```js
window.fetch = async (...a) => { const u=String(a[0]); const r=await origFetch(...a);
  if (u.includes("status=active")) await new Promise(res=>setTimeout(res,1500)); return r; };
```

然後點「全部」→「未完成」（回應被延遲 1.5 秒）→「已完成」（立即回應），等待 3 秒後讀取：


較舊的 `active` 回應確實在 `completed` 回應**之後**才抵達，畫面仍停在「已完成／TodoB」，**未被舊回應覆蓋**。S-5 成立。（驗證後已 `window.fetch = origFetch` 還原。）
