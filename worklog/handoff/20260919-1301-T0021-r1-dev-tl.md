### 我做的假設與決策（含理由）

1. **把 `test:integration` 的 glob 收斂為 `tests/integration/*.test.ts`，QA 那組另開 `test:integration:qa`**（這是本次最重要的一個技術決定）。
   - 起因：合併後 `tests/integration/qa/**/*.qa.test.ts` 會被舊 glob `tests/integration/**/*.test.ts` 掃進來，而 `.github/workflows/ci.yml` 的 `integration` job **沒有啟動服務**（既有測試走 `app.inject()`，在進程內呼叫，本來就不需要服務）。QA 那組是真實 HTTP 打 `$BASE_URL`，服務沒起就會整批連線失敗——**這會直接把 CI 打紅**。
   - 為何不改 `ci.yml` 補起服務：那是 dev-ops 的檔案，且會讓 CI 的 integration 階段一次扛兩種前提完全不同的測試；`qa-tests.yml` 的 `integration-qa` job 本來就已經先起服務再跑，職責分得很清楚。
   - 取捨：代價是「跑一條指令就涵蓋全部整合測試」不再成立，必須跑兩條。已在 README「測試分層」與任務卡審核紀錄表寫清楚，並提醒 qa-lead 重跑時要跑兩條。
2. **新增 `tsconfig.e2e.json` 而不是把 `"DOM"` 加進 `tsconfig.test.json`**。
   - 起因：qa-at 的分支基底 `153410b` 早於 T-0025 新增 `tsconfig.test.json`，所以他們跑 `npm run lint` 時 `tests/**` 根本沒被 `tsc` 檢查。合併後 `lint` 立刻紅了 16 個錯：`tests/e2e` 的 `page.evaluate()` 回呼用到 `document`／`HTMLInputElement`（TS2584／TS2304），加上 `noUncheckedIndexedAccess` 的 TS18048。這是**合併整合產生的問題，不是 qa-at 的測試邏輯問題**。
   - 為何分開：e2e 的 `page.evaluate()` 回呼在瀏覽器裡執行，該有 DOM 型別；但 `tests/unit`／`tests/integration` 跑在 Node 進程內，若也拿到 DOM 全域，誤用 DOM API 會通過型別檢查卻在執行時炸掉。兩個 project 各自只拿到該有的全域型別。
3. **`tests/e2e/nfr-compat.e2e.test.ts` 加三行型別收斂**（`if (!a || !b) continue;`）：`noUncheckedIndexedAccess` 下 `validBoxes[i]` 回傳 `T | undefined`。`i`／`j` 都在長度內，這純粹是型別收斂，**不改任何斷言、不改測試邏輯**，符合提示詞「測試碼本身因合併／型別設定明顯需調整時可小修並記錄」。
4. **`tests/e2e/playwright.config.ts` 檔頭註解改寫**：原文寫「本卡在 worktree 內以 `npm install --no-save` 臨時安裝、是否正式併入交 dev-tl 決定」，合併後已成為過時事實（會變成第二份真相）。改為記載已釘選 1.63.0 與新的執行方式。同理改了 `qa-tests.yml` 檔頭註解。
5. **`@playwright/test` 釘死 `1.63.0` 不帶 `^`**：Playwright 的套件版本與 `npx playwright install` 下載的瀏覽器二進位檔是一對一綁定的，浮動版本會讓兩者對不上。Leader 裁決本就寫「鎖版」。
6. **本次 e2e 只跑 Chromium 兩組**：提示詞明文「e2e 用 `npx playwright install chromium` 後跑一次 Chromium」。Edge／Firefox 留給 qa-at r2 與 Gate 2 後待辦。
