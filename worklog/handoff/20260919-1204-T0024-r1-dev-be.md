  4. **`startup-migrate.test.ts` 用隔離 schema 而非隔離資料庫或直接 DROP 共用表**：任務卡背景給了「臨時資料庫或用臨時 schema」兩個選項；因為 `node --test` 對多個測試檔案是各自獨立的 OS 行程，且 CI／本機常常整批同時跑 `tests/integration/**`，若直接對共用的 `public.todos` 做 DROP，會和同時執行的 `todos-api.test.ts`／`todo-repository.test.ts` 互撞（它們假設 `public.todos` 一直存在）。改用專屬 schema `startup_migrate_test`，透過 `DATABASE_URL` 加 `options=-c search_path=startup_migrate_test`，讓 `runMigrations`／`todo-repository` 內未加 schema 前綴的 `todos`／`schema_migrations` 都落在這個隔離 schema，每次測試前後都整個 `DROP SCHEMA ...
